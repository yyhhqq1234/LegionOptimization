# 安全围栏规格（Safety Fence Spec）— t4 / p-safety

> 性质：纯规格，不含代码。本文是 Legion 重构（RL 功耗控制器）的安全围栏契约。
> 上游接口：t1（HAL 分层 / State48 / Action7 / Reward 权重 / 5 档 8 子模包络）。
> 适用硬件：Lenovo Y7000 2025 IAX10（Ultra 7 255HX / Arrow Lake-HX / RTX 5060 Laptop）为基准机；
> 静态兜底包络沿用现有机型值：Quiet 3.8GHz/25W、Balance 4.8GHz/40W、Beast 5.0GHz/65W、Extreme 5.2GHz/65W。
> 核心原则：**策略只做建议，围栏做强制**。围栏为非学习、版本化、可独立测试的硬逻辑，
> 位于策略输出与执行器（powercfg / ThrottleStop / LLT）之间。任何策略动作必须经过围栏裁决后才能下发。

---

## 0. 总则与优先级

### 0.1 防御纵深（5 层）

| 层 | 名称 | 说明 |
|----|------|------|
| L0 | 传感校验 | 传感器有效性门（超时/野值/冻结检测），故障时按保守假设处理 |
| L1 | 围栏裁剪（Shield-clip） | 对策略动作做限幅/否决/替换，输出合法设定点 |
| L2 | 监督跳闸（Supervisory trip） | L1 无法收敛或越二级阈值时强制降档 + 策略暂停 |
| L3 | OS/EC 回退 | 切回静态 Fn+Q（.bat 包络）或系统电源计划，策略完全旁路 |
| L4 | 人工接管 | EC/BIOS 原生保护为最终底线（本围栏阈值必须留出余量，不得依赖 L4 做常规保护） |

### 0.2 仲裁优先级（高 → 低，绝对优先，不可反转）

```
温度Shield（§1） > 供电/拔电回退（§4） > 功率电气上限（PL2/电流墙，§3 约束内） > 流畅Shield（§2） > Burst预算会计（§3）
```

- 高优先级可否决/覆盖低优先级；低优先级永不放宽高优先级的裁决。
- 同一 tick 有多条触发时，执行最保守动作的并集，并记录全部触发源（审计用）。
- 围栏裁决结果（触发了哪条、裁剪量）必须回写为状态特征 + Reward 惩罚项输入（接口见 §7），让策略学会不触线。

### 0.3 通用执行语义

- 决策节拍：围栏以 ≥2Hz 运行（每 tick ≤500ms 对设定点做一次裁决）；监督跳闸为异步事件驱动（不受节拍限制）。
- 去抖与迟滞：所有越阈触发需连续 N 个采样确认（默认 N=3）；解除需回落到迟滞带以下并持续 T_hold（默认 30s 温度 / 10s 流畅），防振荡。
- 单步限幅：除 L2/L3 跳闸外，单 tick 向下不超过 1 档包络；向上恢复逐档爬升（每档间隔 ≥5s）。
- 故障保守：任一关键传感器（§1.1/§4.1）状态未知 → 按最保守假设处理（温度按超温、供电按 DC 处理）。
- 版本化：围栏逻辑、阈值表、包络表三者独立版本号，联合 pinning（§5.5），任何线上变更走影子/金丝雀（§5）。

## 1. 温度 Shield（Temperature Shield）

### 1.1 信号与采样

| 信号 | 来源 | 采样 | 滤波/有效性 |
|------|------|------|--------------|
| CPU Package 温度 | MSR/HWiNFO 级 CPU 温度源 | 500ms | 3 点中值 + EWMA（α=0.4）；>2s 无更新判 stale |
| 最热 P-core 温度 | 同上 | 500ms | 同上；取 max(P-core) |
| GPU 温度 | NVML | 500ms | 同上；>2s 无更新判 stale |
| VRM/主板温度（如可用） | EC/厂商传感器 | 1s | 仅作 L2 参考，不做 L1 主判据（缺失不降级） |
| 风扇转速/占空比（观测） | EC/LLT | 1s | 仅观测与联动参考，不替代温度判据 |

- 野值剔除：单点跳变 >15°C 且相邻点不支持 → 剔除并计数；野值率超 10%/min 判传感器可疑 → 按 stale 处理。
- 以 **Package 与最热 P-core 的较高者** 为 CPU 域判据；CPU 域与 GPU 域独立裁决、就高执行。

### 1.2 阈值表（默认，Arrow Lake-HX 基准，可按机型表覆盖）

| 等级 | CPU 域（Package/max P-core） | GPU 域 | 语义 |
|------|------------------------------|--------|------|
| WARN | ≥90°C | ≥80°C | 预警：记 log，Burst 预算冻结 refill（只出不进），通知状态位 |
| L1 SOAK（软裁剪） | ≥95°C | ≥85°C | 限幅：PL1 降一档包络 + 频率上限 −200MHz + Burst 归零（§3.4） |
| L2 TRIP（监督跳闸） | ≥98°C 或 L1 持续 60s 未回落 | ≥88°C 或 L1 持续 60s 未回落 | 跳闸：强制 Quiet 等效地板（§1.3）+ 策略暂停 + burst 锁定 |
| L3 CRIT（临界） | ≥100°C | ≥90°C | 临界：立即 L3 回退（静态 Quiet .bat + 策略旁路），需人工/自动冷却重武装 |

- EC/BIOS 硬保护（TJMax/关机点，约 105°C 级）必须高于 L3 ≥5°C，本围栏永不触碰该余量。
- DC（电池）模式下 L1/L2 阈值各 −2°C（散热与功耗余量更小）。

### 1.3 各级动作

- **WARN**：仅记录 + 状态位 + 停止 burst 补充；不改设定点。
- **L1**：输出 = min(策略设定点，当前包络下一档上限，频率上限−200MHz)；burst 可用量清零并暂停新的 burst 批准；每 tick 至多再降一档。
- **L2**：设定点 = Quiet 地板（3.8GHz / PL1 25W / 禁 burst，DC 下再按 §4 取更低者）；
  策略输出旁路（保持最后 L2 设定点，不再跟随策略）；упреждение 风扇：请求最高允许风扇档（通过 LLT/EC 接口，只请求不保证）。
- **L3**：执行 L3 回退（调用静态 `quiet.bat` 等效 + powercfg 落地 + kill 策略下发通道）；策略保持暂停。
- **重武装（re-arm）**：L2 解除条件 = CPU 域 <80°C 且 GPU <70°C 持续 30s → 逐档恢复；
  L3 解除条件 = 同上持续 60s +（自动重武装需金丝雀配置显式允许，否则需人工确认，默认自动但限速恢复）。

### 1.4 与 Burst/流畅的关系

- 温度 L1 及以上：burst 一律拒绝（预算再多也不批），流畅 shield 的"升档请求"一律否决（§2.5）。
- 温度裁决量（被砍掉的功率/频率）计入 Reward 温度惩罚项的归一化输入（§7）。

## 2. 流畅 Shield（Fluency / Anti-stutter Shield）

目标：阻止节电类动作造成可感知的卡顿；只保下限（否决降功耗 / 要求维持或升一档），永不要求突破温度与功率上限。

### 2.1 信号与采样

| 信号 | 来源 | 窗口 |
|------|------|------|
| 前台帧时间 p95 / p99 | PresentMon/DXGI 统计（游戏/全屏应用） | 5s 滑动窗口，每 1s 评估一次 |
| 1% Low FPS（游戏时） | 同上折算 | 同一窗口 |
| 连续 jank 帧数（>33ms@60Hz 目标，或 >1.5× 当前刷新率帧间隔） | 同上 | 窗口内计数 |
| DWM 丢帧/合成卡顿（桌面场景） | DWM 统计 | 5s 窗口 |
| 前台应用类别 | 前台窗口分类：game-fullscreen / interactive / video-call / idle-desktop | 每次评估 |

- 基线（baseline）：同一应用类别下过去 15min 的 p95 中值（滚动基线）；新应用前 2min 为预热期（不触发降级判据，只记录）。
- 无帧数据时（如纯桌面 idle）：流畅 shield 静默（不做任何裁决），避免误伤。

### 2.2 触发判据（前台为 game-fullscreen / interactive 时有效）

任一成立即触发（需连续 2 个评估窗口确认，防抖）：

1. **p95 退化**：窗口 p95 > 基线 ×1.15；
2. **1% Low 跌落**：窗口 1% Low < 基线 ×0.80（游戏场景）；
3. **jank 簇发**：窗口内 jank 帧 ≥12 帧，或连续 jank ≥6 帧；
4. **DWM 退化**（桌面交互场景）：DWM 丢帧率 >5%/窗口。

video-call 类：判据放宽（p95 系数 1.25，jank 阈值 ×2），优先保音频不断续而非帧率。
idle-desktop：不触发。

### 2.3 动作

- 触发后：**否决一切降档/降频/降 PL 动作**（冻结在当前档或上一次流畅时的档）；若当前已处于退化中且温度允许，**上调一档包络**（限单次，需重新评估）。
- **保持期（hold）**：触发后至少保持 10s 不再接受降功耗动作；恢复条件 = 连续 3 个窗口无判据命中 → 解除，控制权交还策略。
- 单调性：一次流畅事件最多上调一档；如仍退化，只延长 hold，不连续爬升（防与温度 shield 对冲）。

### 2.4 防护

- 预热期、切应用/切分辨率/加载画面（帧时间天然尖刺）期间：用"切场抑制"——前台切换后 5s 内不评估退化判据（jank 簇发除外且阈值 ×2）。
- 后台重负载（编译/渲染）+ 前台 idle：不触发（以前台类别为准）。

### 2.5 冲突规则

- 与温度/L2/DC 回退冲突时，温度与供电永远胜出；流畅 shield 的升档请求被否决记为一次"被压制事件"（ counted，用于 SLO §6.3 的权衡分析）。
- 流畅触发期间的 burst 申请：仅当温度 WARN 以下且预算充足时可批，否则拒绝。

## 3. Burst 预算（Burst Budget）

模型：**令牌桶（token bucket）**，能量单位。持续包络以上部分按实际功耗积分扣费。

### 3.1 会计模型

- 桶容量：C（kJ）；补充速率：r（W，即 J/s）；仅当实际功耗 < 持续包络且温度 < WARN 时补充。
- 扣费：当 P_actual > P_sustained（当前档持续 PL1）时，dBucket/dt = −(P_actual − P_sustained)；否则 dBucket/dt = +r（上溢截断于 C）。
- 批准条件（全部满足才批）：桶余量 > 本次申请预估能量 ×1.2 安全系数；温度域无 WARN 及以上；DC 模式下按 §4 降额或禁用；单次 burst 时长 ≤ Tmax；两次 burst 间隔 ≥ Tmin_gap。
- 桶状态（余量%、 refill/ tec 速率）为 State 必选特征（§7），让策略可学。

### 3.2 默认参数表（初始值，金丝雀可调，调整走 §5）

| 档位 | P_sustained（PL1） | P_burst_max | Tmax（单次上限） | C（桶容量） | r（补充速率） | Tmin_gap |
|------|-------------------|-------------|------------------|-------------|---------------|----------|
| Quiet | 25W | 40W | 10s | 0.15kJ | 3W | 60s |
| Balance | 40W | 65W | 28s | 0.70kJ | 5W | 45s |
| Beast | 65W | 95W | 20s | 0.60kJ | 8W | 60s |
| Extreme | 65W | 110W | 15s | 0.675kJ | 10W | 90s |

- 容量校验示例（Balance）：(65−40)W×28s = 700J = 0.70kJ，恰满桶一次长 burst；设计意图即"满桶换一次标准 burst"。
- GPU 功耗不计入本桶（CPU 域专用桶）；整机墙/适配器墙由 §4 与 EC 保证，整机级 burst 需双机验证后另立桶（本期不做，列为待确认 §7）。

### 3.3 越界语义

- 超 Tmax 未降回：围栏强制把 PL1 拉回 P_sustained（记一次 burst 违规，策略 Reward 扣分）。
- 桶空后仍请求 burst：拒绝并钳制到 P_sustained；连续 3 次空桶请求 → 冻结 burst 申请 5min（防策略"撞墙"循环）。
- 温度 WARN 即冻结 refill（只出不进）；L1 及以上清零可用量（桶记 0 但不清"欠费"，恢复后从 0 开始补充）。

### 3.4 DC 模式降额

- DC 默认：**禁用 burst**（P_burst_max = P_sustained_DC）；仅当电量 ≥60% 且用户显式允许"DC 性能模式"时，按 AC 表的 50% 启用（C、Tmax 均减半）。
- 拔电瞬间：在途 burst 立即终止（§4.2）。

## 4. 拔电回退（AC→DC Fallback）

### 4.1 检测

- 主信号：系统电源状态（AC/DC）事件 + 轮询（≤1s）；事件驱动优先，轮询兜底。
- 去抖：AC→DC 切换立即采信（0 去抖，宁可误报不可迟报）；DC→AC 回切需稳定 2s 确认（防插头抖动）。
- 状态未知（API 失败/超时）：**按 DC 处理**（保守默认）。

### 4.2 AC→DC 即时动作（<1s 落地）

1. 终止在途 burst，桶冻结；
2. 设定点钳制到 **DC 安全包络**（§4.3），频率/PL1/powercfg DC 值一次写全；
3. powercfg 切 DC 值（`setdcvalueindex` 系）并 `setactive` 落地；
4. dGPU 策略：默认请求切 Hybrid/iGPU 偏好（仅请求，切换失败不阻塞前三项；显式全功耗 DC 场景需用户白名单）。

### 4.3 DC 持续包络（独立表，与 AC 解耦）

| DC 档 | PL1 | 频率上限 | burst | 适用 |
|-------|-----|----------|-------|------|
| DC-1（性能） | 35W | 4.2GHz | 禁用（除 §3.4 例外） | 电量 ≥60% |
| DC-2（均衡） | 25W | 3.8GHz | 禁用 | 电量 20–60% |
| DC-3（省电） | 15W | 3.0GHz | 禁用 | 电量 <20% |

- 电量 <10%：强制 DC-3 + 系统级低电量通知（只通知不关机，关机归 OS 管）。
- DC 下温度阈值 −2°C（§1.2），流畅 shield 判据不变但升档上限为 DC-1。

### 4.4 回插（DC→AC）恢复

- 确认 AC 稳定 2s 后：从当前 DC 档**逐档爬升**（每档停留 ≥5s 且温度无 WARN），不允许直跳 Extreme。
- burst 桶从 0 起补（不继承拔电前余量）。
- AC 抖动（5min 内 ≥3 次 AC/DC 翻转）：锁定 DC-2 30min 并告警（防插头接触不良导致反复横跳）。

## 5. 影子 / 金丝雀流程（Shadow / Canary）

任何策略版本、围栏阈值表、包络表的线上变更必须走本流程；**静态 Fn+Q（.bat）为最终 LKG（last-known-good），一键回退目标**。

### 5.1 阶段划分与准入

| 阶段 | pomoc | 准入条件 | 时长/样本 |
|------|------|----------|-----------|
| Shadow（影子） | 新逻辑只推理、不下发；输出经围栏试算并全量记 log | 上一阶段 CI 门禁通过（围栏单元测试 + 回放测试零 L2+ 误放行） | ≥8h 有效覆盖，含游戏 ≥2h + 办公 ≥2h + idle ≥1h + 至少 1 次插拔电 |
| Canary（金丝雀） | 小范围真实下发 | Shadow 门禁（§5.2）通过 + 人工确认 | 先本机 48h；双机扩展需第二台机器 24h（t2 验证矩阵机） |
| Rollout（放量） | 全量 | Canary 门禁（§5.3）通过 + 人工确认 | 逐档放量，保留一键回退 |

### 5.2 Shadow 通过门禁（全部满足）

1. 动作一致率：影子 vs 在运版本在同类场景下设定点档位一致率 ≥85%（分歧点需个案说明温度/流畅归因）；
2. 试算跳闸率：影子输出经围栏试算的 L1+ 触发率 ≤ 在运版本实际触发率 +2pp，且 **L2+ 试算触发 = 0**；
3. 流畅中性：影子窗口 p95/1% Low 与同期实际差值在 ±5% 内（同应用类别对比）；
4. 零崩溃：影子推理零异常/零超时（超时预算 50ms/推理，§6.2）；
5. 日志完整率 100%（§5.5）。

### 5.3 Canary 通过门禁与自动回滚

- 通过门禁：48h 内 L2+ 跳闸 = 0；流畅 SLO（§6.3）达标；温度 SLO（§6.1）达标；无 AC/DC 回退失败；用户无"明显变卡/变烫"主观否决。
- **自动回滚触发（任一即回滚）**：L3 触发 1 次；L2 24h 内 ≥2 次；流畅 SLO 小时级 burn 超阈（§6.5）；执行器连续 3 次下发失败；看护人一键否决。
- 回滚动作：60s 内切 LKG（静态 Fn+Q 当前档 .bat + powercfg 落地），冻结金丝雀版本，保留现场 log（§5.5），回滚演练每季度至少 1 次（SLO §6.4）。

### 5.4 Canary 期流量策略（单机）

- 单机无分流概念，采用**时间片 A/B**：金丝雀与 LKG 按整小时交替（偶数小时金丝雀），对比同类别负载窗口；前台游戏时段优先排金丝雀以收集关键样本，但 L2+ 历史包袱机（过去 7d 有 L2）当日只跑 LKG。
- 双机阶段：副机先跑对照（LKG），主机跑金丝雀，24h 后交换（交叉验证）。

### 5.5 可观测与版本 pinning

- 每决策记录：{policy_ver, fence_ver, envelope_ver, state_hash, action_raw, shield_verdict(+触发源), setpoints_final, temps, power, AC/DC, burst_bucket, fluency_stats}；本地环形缓冲（≥24h）+ 评估 log 持久化（canary 全程）。
- 三版本号联合标注于每条 log 与每次跳闸报告；复现要求：给定三版本 + log 可完整重放裁决。
- 跳闸报告必填：触发源、阈值、持续/峰值、恢复过程、是否触自动回滚。

## 6. SLO 定义

### 6.1 安全 SLO（最高优先级，违例即停金丝雀）

| SLO | 目标 | 窗口 |
|-----|------|------|
| S1 持续高温 | 1s 采样 CPU 域 p99.9 <95°C | 7d 滚动 |
| S2 跳闸零容忍 | L3 次数 = 0；L2 ≤1 次/7d | 7d 滚动 |
| S3 传感器健康 | stale/可疑样本率 <0.1% | 24h |
| S4 裁决延迟 | 围栏裁决 p99 <50ms/tick（L2/L3 事件路径 <200ms 落地） | 24h |

### 6.2 决策链路 SLO

| SLO | 目标 | 窗口 |

### 6.5 告警与错误预算

- Burn-rate 双轨：fast-burn（1h 窗，预算消耗 >10%）→ 立即告警 + canary 自动回滚候选；
  slow-burn（24h 窗，预算消耗 >30%）→ 工单 + 冻结放量。
- 安全 SLO（S1/S2）无错误预算概念：违例即按 §5.3 回滚 + 复盘，不做"预算内接受"。
- 体验/可用性 SLO 按 30d 错误预算管理，预算耗尽即冻结 Rollout 直至复盘。

## 7. 对上游（t1）与下游（t5）的接口要求

1. **输入**：围栏需要 State48 至少包含：CPU package/最热核/GPU 温度（滤波前+滤波后）、AC/DC 状态、电量%、前台应用类别、帧统计（p95/1%Low/jank 计数）、burst 桶余量、当前包络档位、风扇观测；缺失项必须在 t1 规格中标记为 P0 补齐，否则本围栏对应条款降级为"保守常闭"（温度按超温/供电按 DC/流畅按静默）。
2. **输出**：围栏向执行器输出最终设定点；同时向策略回写 `shield_verdict`（触发源 bitmask + 裁剪量），t1 的 Reward 权重必须包含温度越线、burst 违规、流畅退化三项惩罚（权重值由 t1 定，存在性由本规格强制）。
3. **待 t5 汇总确认**：GPU 独立 burst 桶是否立项（本期不做）；第二台验证机型号与 EC 阈值差；DC-1 档 35W 是否需按适配器功率（170W/230W 级）分表。
4. **非目标**：不替代 EC/BIOS 硬保护；不承诺电芯寿命/电池健康量化目标；不覆盖 dGPU 超频/电压修改（本期围栏只管 CPU PL/频率 + 整机功耗墙内的 CPU 侧，dGPU 侧仅做整机墙联动与 DC 偏好请求）。
